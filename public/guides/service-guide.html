1. 서비스 이용 순서

모두의박스는 페이를 충전하고 포인트와 페이로 박스를 구매한 뒤, 당첨 상품을 배송받거나 포인트로 전환하는 서비스입니다. 페이는 환전 신청이 가능하고 포인트는 환전할 수 없습니다. 이 구분을 먼저 이해하면 결제와 상품 처리 화면을 쉽게 사용할 수 있습니다.

  1. 회원가입과 로그인 후 마이페이지에서 보유 페이와 포인트를 확인합니다.
  2. 페이 충전에서 금액·결제수단·추가 포인트를 확인하고 승인합니다.
  3. 랜덤박스에서 구성품과 최종 확률을 확인한 후 수량과 쿠폰을 선택합니다. 포인트를 먼저 쓰고 부족한 금액만 페이에서 차감합니다.
  4. 개봉 결과를 확인합니다. 애니메이션을 건너뛰어도 이미 정해진 상품은 바뀌지 않습니다.
  5. 보관함에서 배송을 신청하거나 상품을 포기하고 표시된 포인트를 받습니다.

화면 이용 범위

현재 화면은 브라우저에 기록을 저장합니다. 같은 브라우저의 관리자와 사용자 화면에서 처리 결과를 확인할 수 있습니다. 다른 기기에는 기록이 공유되지 않습니다. 실제 DB, 본인인증, PG 승인, 계좌 송금, 택배 접수, 문자 발송과 서버 예약 작업은 연결되어 있지 않습니다.

기본 체험 설정에서는 빈 입력으로 가입·로그인·결제 흐름을 확인할 수 있습니다. 관리자가 필수 동의 확인을 켜면 필수 항목에 동의해야 진행됩니다. 실제 비밀번호나 카드정보는 입력하지 않습니다.

2. 페이와 포인트 관리

구분사용 기준
페이직접 충전한 잔액입니다. 1페이=1원 상당이며 환전 신청할 수 있습니다.
포인트충전 보너스·상품 포기·이벤트 등으로 지급합니다. 박스 구매에 쓰며 환전할 수 없습니다.

충전과 이용 내역

마이페이지의 페이 충전에서 금액을 선택합니다. 승인 전 충전 페이와 추가 포인트를 따로 확인하세요. 지갑에는 두 잔액과 이용 내역이 표시됩니다. 예를 들어 10,000원 박스 구매 시 포인트가 3,000P 있으면 3,000P와 7,000페이가 사용됩니다.

충전 취소

지갑의 충전 내역에서 미사용 충전 취소를 누릅니다. 이미 취소된 금액을 제외한 남은 원금과 회수할 보너스를 확인합니다. 원금이나 포인트가 부족하면 취소가 제한되므로 고객센터에 문의합니다. 관리자 부분 취소도 원금과 비례 보너스를 함께 정산합니다.

페이 환전

  1. 마이페이지의 페이 환전에서 신청 금액을 입력합니다. 포인트는 신청 대상이 아닙니다.
  2. 금액과 포인트 환전 불가 안내를 확인하고 신청합니다. 신청 즉시 해당 페이가 예약 차감됩니다.
  3. 신청 상태에서는 직접 취소할 수 있습니다. 취소·거절 시 예약 페이가 한 번 반환됩니다. 승인 시 추가 차감은 없습니다.

환전 승인은 화면상의 처리 상태이며 실제 송금 완료 증빙이 아닙니다. 별도 만료일이 없는 잔액은 기본 무기한이며 현재 자동 잔액 소멸을 실행하지 않습니다.

3. 박스 구매와 상품 확인

  1. 랜덤박스에서 이름·카테고리로 찾습니다. 담기는 장바구니, 하트는 관심 박스로 연결됩니다.
  2. 박스 열기를 누르면 구매 화면이 나옵니다. 상품별 이미지·등급·재고·최종 확률을 확인합니다. 상품명을 누르면 브랜드·사양·구성·기준가격·상세 설명을 볼 수 있습니다.
  3. 수량과 쿠폰을 선택합니다. 버닝 이용권이 있다면 적용 가능한 박스에서 선택하고 바뀐 확률을 확인합니다.
  4. 포인트 사용액, 페이 사용액, 총 결제금액과 상품 수령 기한을 확인한 후 구매합니다. 가입할 때 등록한 연락처를 다시 입력할 필요는 없습니다.

여러 개를 한 번에 개봉하면 순서대로 결과가 결정됩니다. 각 회차에서 게이지가 달라질 수 있어 첫 회차 확률이 전체 회차에 똑같이 적용되지는 않습니다. 나의 언박싱에서 개별 기록의 실제 적용 확률표를 확인합니다.

확률을 읽는 방법

1%는 같은 확률로 반복할 때 평균 100회당 1회라는 뜻이며 100회 안에 반드시 당첨된다는 뜻은 아닙니다. 같은 1%가 유지되는 독립 추첨에서 100회 중 한 번 이상 당첨될 가능성은 약 63.4%입니다. 게이지로 확률이 바뀌면 이 고정확률 계산과 실제 결과를 구분해야 합니다.

4. 개봉 게이지 이해하기

사용자 화면에서는 개봉 게이지, 관리자 메뉴에서는 천장 게이지로 표시합니다. 현재 방식은 누적 결제금액으로 상품을 확정 지급하지 않습니다. 정해진 개봉 횟수 이후 해당 등급에 당첨될 때 그 등급의 게이지가 쌓입니다. A~E는 서로 독립적입니다.

  1. 적립 시작 개봉수를 채웁니다. 시작값이 10이면 첫 10회 뒤부터 해당 등급 당첨 시 적립합니다.
  2. 설정된 증가량만큼 해당 당첨 등급 게이지가 올라갑니다. 다른 등급 게이지를 대신 올리지 않습니다.
  3. 100%가 되면 다음 개봉부터 정해진 횟수만큼 확률을 높입니다. 준비된 등급 중 A→E 순서로 하나를 적용합니다.
  4. 적용 횟수를 모두 쓰면 해당 게이지만 0이 됩니다. 대상 상품이 없거나 이미 해당 등급이 100%라면 강화 횟수를 쓰지 않습니다.

예를 들어 A등급 기본 합산 확률 2%에 +5%p를 적용하면 7%가 됩니다. 나머지 등급 합계는 93%가 되도록 비례 조정합니다. 최대값은 100%이며 게이지 100% 자체가 상품 당첨을 보장하지 않습니다.

현재 시연 초기값은 A·B 활성, 시작 10회, 해당 등급 당첨 시 20% 적립, 확률 +5%p, 강화 1회입니다. 운영 확정값이 아니며 관리자가 바꿀 수 있습니다. 새 제도 이전 개봉은 소급하지 않아 게이지 적용 개봉과 전체 언박싱 건수가 다를 수 있습니다. 이전 확정보상은 별도 이력에서 조회만 합니다.

5. 보관함과 상품 포인트 전환

배송받을 상품

보관함에서 상품을 선택해 배송 신청을 누릅니다. 수령인·주소·배송비를 확인하고 필요한 정보 제공에 동의합니다. 주문·배송에서 상태와 송장을 확인할 수 있습니다.

상품을 포기할 때

상품 포인트 전환을 누르면 기준가격, 당첨 당시 반환율, 지급 포인트가 표시됩니다. 기본 반환율은 60%이며 상품별 비율이 있으면 우선합니다. 기준가격 100,000원과 반환율 60%이면 60,000P입니다. 0%도 유효한 설정이므로 지급액이 0P인지 확인해야 합니다.

소수점 아래는 버립니다. 당첨 당시 반환 조건을 저장하므로 이후 설정 변경으로 이미 보관한 상품의 금액이 달라지지 않습니다. 과거 고정 전환액을 보존한 상품은 현재 비율을 다시 계산하지 않고 기존 확정 반환액을 동일 금액의 포인트로 표시합니다. 포인트는 환전 불가입니다.

전환 후 상품 복구가 허용된 경우, 표시된 기한과 하루 허용 횟수 안에서 지급 포인트를 회수하고 상품을 복구합니다. 포인트가 부족하거나 기한이 지나면 복구되지 않습니다.

수령 기한

새 일반 상품의 기본 기한은 240시간입니다. 미신청 상품은 당시 반환액의 포인트로 전환됩니다. 기한 전 알림함 안내를 확인하세요. 배송 신청 상품·이전 확정보상 등 제외 대상과 기한 없는 과거 상품을 구분합니다. 실제 상시 자동 작업과 문자 발송은 연결되지 않습니다.

6. 품절 대체와 취소 문의

  1. 품절 상품의 대체 제안은 보관함 상단에서 확인합니다. 원상품·대체 상품·사유·상태를 비교합니다.
  2. 수락하면 배송 대상이 대체 상품으로 연결됩니다. 원당첨 결과, 당시 확률과 반환 기준은 유지됩니다.
  3. 거절하면 원상품을 유지합니다. 이후 배송이나 취소 방법은 고객센터에 문의합니다.
  4. 제안 대기 중에는 배송·전환을 진행할 수 없습니다. 신청 기한이 끝나면 제안이 종료되고 예약 재고가 반환됩니다.

취소·반품 신청은 상품 포기와 다른 절차입니다. 하자·오배송·배송 지연·청약철회 사유와 대상 거래를 선택해 접수합니다. 상품 반환율을 법정 청약철회에 일괄 적용하지 않습니다. 실제 회수나 PG 취소는 별도 연결이 필요합니다.

문의 후 확인

고객센터의 나의 문의에서 접수 상태와 답변을 확인합니다. 상품·주문 번호를 함께 적으면 운영자가 기록을 찾기 쉽습니다. 개인정보 권리 요청, 계정 복구, 회원 탈퇴 요청도 처리 내역을 남기는 접수 기능이며 실제 인증 메일이나 개인정보 삭제를 자동 실행하지 않습니다.

7. 혜택과 개인 메뉴

메뉴확인할 내용
누적 결제 혜택이벤트 기간 안의 유효 충전금과 회차별 목표를 확인합니다. 취소금은 제외하고 반복 이벤트는 다음 목표를 채워야 합니다.
출석체크와 친구 초대출석은 한국 시간 기준 하루 한 번입니다. 추천 코드를 등록하고 충전 조건을 충족하면 설정된 양쪽 보상을 받습니다.
내 쿠폰과 이용권유효기간·잔여횟수·최소금액을 확인합니다. 특별 박스와 버닝 이용권은 적용 조건에 맞게 사용합니다.
선물함과 포인트샵운영자가 활성화한 기능만 이용합니다. 상품·잔액·제한을 확인하며 포인트는 환전되지 않습니다.
알림수령 마감과 처리 결과를 확인합니다. 실제 문자·메일 발송과 구분됩니다.
언박싱과 커뮤니티공개 설정에 따른 기록과 게시물을 확인합니다. 브라우저 기록을 전체 실회원 검증 결과로 해석하지 않습니다.
회원정보와 약관닉네임·연락처·공개 선택·마케팅 선택을 관리합니다. 필수와 선택 동의를 구분합니다.
거래 명세본인의 충전·주문 기록과 당시 정책을 확인합니다. PG 영수증이나 세금계산서는 아닙니다.

공지사항·이벤트·자주 묻는 질문·이용방법·확률 안내·사업자 안내는 해당 메뉴에서 확인합니다. 지급 포인트는 현금 보상과 구분하며 누적 혜택은 개봉 게이지와 별도입니다.

8. 관리자 업무 시작하기

관리자는 목록에서 필수 항목을 비교한 후 상세보기를 눌러 행 아래에서 전체 값과 기록을 확인합니다. 메뉴 검색으로 화면을 찾고 필터를 사용해 대상을 좁힙니다. 변경 전 회원 ID와 상품 ID를 먼저 확인하세요.

  1. 상품 등록·재고에서 구성 상품을 준비합니다.
  2. 랜덤박스 관리와 상품별 당첨 확률에서 박스 구성과 합계 100%를 확인합니다.
  3. 페이 충전·보너스, 상품 포인트 전환 설정, 천장 게이지에서 운영값을 저장합니다.
  4. 배송비·배송 정책과 약관·정책에 실제 안내를 입력합니다.
  5. 사용자 화면에서 가입·충전·구매·배송 또는 포인트 전환을 확인하고 관리자 원장과 대조합니다.

저장 오류가 나면 메시지에 표시된 필수값·금액·단위·기간·재고를 먼저 수정합니다. 실패한 작업을 완료로 안내하지 마세요. 다른 탭에서 상태가 바뀌었다는 안내가 나오면 최신 상태를 불러온 뒤 다시 확인합니다. 저장소 오류가 해결되기 전 반복 처리하지 않습니다.

현재 공개 관리자 화면에는 실제 서버 권한 통제가 없습니다. 실회원이나 실거래를 관리하는 운영 도구로 바로 사용하지 않습니다. 관리자 역할별 권한과 승인 절차는 실제 서비스 개발에서 구현해야 합니다.

9. 상품과 박스 등록하기

상품 등록 및 재고

  1. 상품 등록·재고에서 이름·A~E 등급·기준가격·재고·판매 상태를 입력합니다. 브랜드·사양·설명도 준비합니다.
  2. 대표 이미지와 상세 이미지는 파일로 업로드합니다. 상품별 반환율을 비워 두면 기본값, 0~100 사이 값을 넣으면 개별값이 적용됩니다.
  3. 저장 후 사용자 상품 상세에서 이미지와 설명을 확인합니다. 잘못된 파일 형식이나 수치는 오류를 수정하고 다시 저장합니다.

랜덤박스와 당첨 확률

  1. 랜덤박스 관리에서 이름·가격·총수량·잔여수량·상태를 입력하고 대표·상세 이미지를 올립니다. 이미지는 수정창에서 관리합니다.
  2. 상품별 당첨 확률에서 상품과 확률을 등록합니다. 중복 상품, 합계 100%, 재고와 판매 상태를 확인합니다.
  3. 저장 후 사용자 결제 화면의 구성품 이미지와 최종 확률을 대조합니다. 재고가 없는 양의 확률 상품이 있으면 판매 상태와 재고를 먼저 수정합니다.

상품 목록의 당첨내역과 판매내역 버튼은 해당 상품 ID 필터를 적용합니다. 목록의 필터 칩에서 해제하거나 다른 메뉴로 이동하면 초기화됩니다. 개봉·당첨 이력에서 당시 확률표를 펼쳐 확인하며 현재 설정값으로 과거 확률을 대체하지 않습니다.

10. 페이와 포인트 처리하기

충전과 원장

페이 충전·보너스에서 선택 금액과 추가 포인트율을 저장합니다. 충전 내역에서 원금·보너스·취소액을 확인하고 필요한 취소 금액을 입력합니다. 처리 후 페이·포인트 원장과 사용자 지갑을 대조합니다.

상품 전환 관리

상품 포인트 전환 설정에서 기본 반환율과 복구 조건을 관리합니다. 상품 등록·재고의 개별 반환율이 기본값보다 우선합니다. 상품 포인트 전환 목록에서는 지급 포인트와 당시 기준가격·비율·기한을 상세보기로 확인합니다. 과거 확정액은 보존하며 현재 비율로 다시 계산하지 않습니다.

페이 환전 승인

  1. 페이 환전에서 신청 회원·금액·상태를 확인합니다. 신청 시 이미 예약 차감되었는지 원장과 대조합니다.
  2. 승인 또는 거절 사유를 입력하고 처리합니다. 승인 시 재차 차감하지 않으며 거절 시 예약액이 반환됩니다.
  3. 사용자 환전 내역과 지갑을 확인합니다. 화면상 승인을 실제 계좌 송금 완료로 안내하지 않습니다.

잔액 조정

회원별 페이·포인트 또는 회원 관리에서 회원을 선택합니다. 페이와 포인트 중 조정할 잔액을 고르고 양수 지급·음수 차감과 사유를 입력합니다. 저장 후 해당 회원의 두 잔액 및 원장을 확인합니다. 페이 조정은 환전 가능한 잔액을 바꾸므로 종류를 반드시 확인하세요.

11. 게이지 운영값 설정하기

관리자 천장 게이지는 회원별 게이지, 게이지·확률 설정, 강화 적용 기록, 이전 보상 기록의 네 탭으로 구성합니다. 결제금액 기반 확정보상 지급과 이전 게이지 금액 정정은 새 거래에서 사용하지 않습니다.

  1. 게이지·확률 설정에서 활성 등급과 시작 개봉수, 해당 등급 당첨 시 증가량, 확률 증가 %p, 강화 횟수를 입력합니다.
  2. 변경 사유를 작성하고 저장합니다. 시작 횟수·증가량·횟수 범위 오류가 나오면 해당 값을 수정합니다.
  3. 회원별 게이지에서 새 규칙 적용 개봉수와 등급별 진행률을 확인합니다. 활성화 전 전체 개봉 기록과 혼동하지 않습니다.
  4. 사용자 개봉 게이지와 결제 화면에서 실제 적용 조건을 비교합니다. 강화 적용 기록에서는 강화 전후 확률과 해당 개봉을 확인합니다.

이미 준비된 강화의 저장된 증가값과 횟수는 당시 조건을 보존합니다. 규칙 변경 후 기존 준비 상태와 새 적립 상태를 구분해 확인하세요. 여러 등급이 준비되면 A→E 순서로 적용 가능한 한 등급을 사용합니다.

이전 보상 기록 탭은 과거 확정보상·정정·정산 기록을 조회하기 위한 화면입니다. 예전 결제금액을 새 개봉 게이지로 바꾸거나 과거 확정보상을 다시 지급하지 않습니다.

12. 주문과 회원 문의 처리하기

배송 처리

  1. 회원 보관함에서 대상 상품과 현재 상태를 확인합니다. 주문·배송 관리에서 구매·이벤트 개봉·배송 신청을 구분합니다.
  2. 배송 신청 건의 주소와 상품명을 확인하고 상태를 변경합니다. 배송 처리에는 택배사와 송장번호가 필요합니다.
  3. 품절로 대체가 필요하면 상품·사유를 제안하고 사용자 수락을 기다립니다. 제안 중 예약 재고와 수락·거절 상태를 확인합니다.
  4. 저장 후 사용자 주문·배송에 수락한 실제 배송 상품명과 송장이 보이는지 확인합니다.

배송비·배송 정책에서 배송비·무료배송 기준·안내를 저장하면 다음 신청 화면에 반영됩니다. 배송비 계산과 실제 비용 청구는 별도입니다.

회원과 문의

회원 관리에서 연락처·상태와 연결 기록을 확인합니다. 1:1 문의에서는 접수 내용을 읽고 답변과 처리 상태를 저장합니다. 취소·반품, 탈퇴, 계정 복구와 개인정보 권리 요청도 내용과 실제 처리 범위를 구분합니다. 답변 저장만으로 외부 메일 발송·계정 인증·정보 삭제가 실행되지는 않습니다.

13. 콘텐츠와 약관 운영하기

  1. 공지사항·자주 묻는 질문에서 제목 또는 질문, 본문, 공개 상태를 입력합니다. 저장 후 사용자 목록과 상세 화면을 확인합니다.
  2. 이벤트에서 기간·금액 조건·보상·최대 횟수를 관리합니다. 기간 역전이나 지급 상품 재고 오류는 먼저 해결합니다.
  3. 쿠폰에서 코드·할인금액·사용 횟수·유효기간·상태를 입력합니다. 사용자 구매 화면에 사용 가능한 쿠폰만 나오는지 확인합니다.
  4. 홈 배너에서 이미지·연결 주소·기간·상태를 관리합니다. 등록 기록이 실제 홈 노출까지 연결되는지 확인하며, 연결되지 않은 항목을 노출 완료로 판단하지 않습니다.
  5. 당첨 공개 설정에서 공개 여부와 이름 가림을 확인합니다. 회원의 비공개 선택은 공개 피드에서 제외되어야 합니다.

약관과 동의

약관·정책에서 사업자 정보, 정책 유형·버전·시행일·활성 상태를 입력합니다. 미래 시행일이나 비활성 정책은 현재 거래에 적용되지 않습니다. 새 기본 정책은 4.0이며 운영자가 수정한 과거 본문을 자동 덮어쓰지 않습니다.

필수 동의 확인은 기본 꺼짐입니다. 켜면 가입·충전·구매·배송·환전의 필요한 확인 항목을 검증합니다. 제3자 제공을 켤 때는 실제 업체, 목적, 항목, 보유기간을 모두 입력하세요. 배송 시 안내와 동의 기록을 보존하며 실제 외부 전송은 실행하지 않습니다.

운영자가 확인할 순서

  1. 대상 회원·상품·거래 ID가 맞는지 확인합니다.
  2. 변경 전 값과 저장할 값을 비교하고 필요한 사유를 입력합니다.
  3. 성공 안내 후 목록과 상세보기에 새 값이 남는지 확인합니다.
  4. 사용자 페이지에서 잔액·상품 상태·안내가 일치하는지 확인합니다.
  5. 오류는 표시된 조건을 고친 뒤 다시 처리하고, 실결제·실배송은 외부 처리 증빙과 별도로 확인합니다.

노트북에서는 표 안을 좌우로 이동해 나머지 열을 확인할 수 있습니다. 상세보기는 행 아래에서 펼쳐지고 긴 수정창은 내부에서 위아래로 이동합니다. 입력·저장·닫기 버튼이 가려지면 화면 확대율과 창 크기를 확인하세요.
