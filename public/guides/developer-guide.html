1. 인수 범위와 실행

이 저장소는 사용자 화면과 관리자 기능을 연결한 React·Vite 프로토타입입니다. 브라우저 안에서 거래와 보상 상태를 변경하며, 실제 서버·DB·PG·본인인증은 연결하지 않았습니다. 현재 화면을 기능 명세의 기준으로 사용하되 서버 권한과 거래 원장은 별도로 구현해야 합니다.

가입·로그인은 빈 입력으로도 진행되도록 의도적으로 허용했습니다. 공개 관리자 경로에도 인증 장벽이 없습니다. 이를 실서비스 인증 설계로 재사용하지 않습니다. 카드번호·실제 비밀번호를 수집하는 결제 폼을 추가하지 말고 PG와 인증 제공자의 화면을 연결합니다.

기존 docs의 조사·기획 자료는 참고 이력입니다. 현재 기능과 정책은 이 문서, 소스, 테스트를 기준으로 확인합니다. 브라우저 저장 내용을 서버에 자동 이전하는 기능은 없습니다.

3. 상태 구조와 거래 계약

저장 키는 modu-meeting-v2입니다. 최상위 version은 2, platform.version은 1입니다. loadState가 구형 상태에 새 설정·보상 배열·등급·카탈로그를 보완합니다. 기존 거래, 이미지와 운영자가 수정한 정책을 보존합니다. migration은 반복 실행해도 시드 상품을 중복 추가하지 않아야 합니다.

데이터주요 내용

platform.probabilityHistory·requests확률 변경 전후와 중복 요청 기록

transition(state, action)은 성공 시 {ok:true,state}, 실패 시 {ok:false,error}를 반환합니다. 실패한 거래를 일부 반영하지 않습니다. App은 저장 성공 후 화면 상태를 바꿉니다. 저장 공간 부족 시 이미지를 줄이도록 안내합니다.

현재 localStorage 동기화는 동일 출처 탭 간 변경 반영입니다. 다중 브라우저 동시 결제, 서버 트랜잭션, 장애 복구나 감사 보안을 보장하지 않습니다. 서버 구현에서 해당 제약을 해결해야 합니다.

4. 금액과 천장 산정

인정 결제금액은 해당 회원의 충전 완료·부분 취소 행에서 원금에서 누적 취소액을 뺀 금액을 합산합니다. 승인 대기·실패·완전 취소는 제외합니다. 무료 지급, 캐시, 쿠폰, 포인트 재사용과 박스 구매금액은 추가 적립하지 않습니다.

등급별 유효 진행액 = 순충전액 + 관리자 정정 합계 − 해당 등급 수령 기준금액 합계입니다. 화면 진행액은 0 이상으로 표시하고, 음수분은 정산 필요액으로 따로 남깁니다. A와 B의 수령 합계는 서로 공유하지 않습니다.

기본 B 10,000,000원, A 40,000,000원입니다. 최초 인정 충전 시 각 회차의 기준을 고정합니다. 기준 변경 후에도 진행 중 회차는 기존 값을 사용하며, 수령 후 다음 회차에 새 기준을 적용합니다. 한 번 수령할 때 한 회차만 차감하고 초과분을 유지합니다.

작업입력과 처리
CHARGEamount·method·requestId. 승인 원금과 보너스 기록 후 누적 보상 확인
REFUND_CHARGEid·memberId·amount. 잔여 원금 내 부분 취소, 보너스 비례 회수, 인정액 재계산
CLAIM_PITYgrade·category·requestId. 조건·재고 확인 후 상품 지급과 해당 회차 소진
ADMIN_CLAIM_PITYmemberId와 reason 추가. 동일 조건을 확인하고 처리 담당·사유 저장
ADMIN_PITY_ADJUSTmemberId·grade·amount·reason. 진행금액만 정정하고 이력 저장
RESOLVE_SETTLEMENTid·note. 검토 메모 저장이며 채무나 잔액을 자동 해소하지 않음

수령은 보관함 확정 지급 시점입니다. 배송 완료 시점과 혼동하지 않습니다. 남성·여성·가전 중 선택한 카테고리의 지급 가능한 지정 상품을 사용합니다. 품절이면 권리를 보존하고 차감하지 않습니다. 실제 대체 상품 제안과 동의 수집은 후속 개발 범위입니다.

5. 확률과 이벤트 및 전환

추첨 조건

상품별 확률은 productOdds 배열로 저장합니다. 합계 100%, 중복 상품, 존재 여부와 재고·상태를 검증합니다. 0%를 포함해 박스에서 참조하는 상품은 참조 해제 전 삭제하지 않습니다. 확률표를 구매 결과에 보존하고 공개 화면과 실제 선택 계산이 같은 데이터를 사용합니다.

기존 6개 박스는 금액대 선택 후 해당 구간 내 재고 상품을 균등 선택합니다. 새 7번 박스는 A~E 개별 확률입니다. 관리자는 기존 박스도 상품별 방식으로 변경할 수 있습니다. 평균 간격은 100/p, n회 중 한 번 이상은 1−(1−p/100)^n이며 보장 횟수로 표현하지 않습니다.

버닝은 지정 박스의 A 합계를 설정 비율로 맞추고 다른 등급 합계를 나머지 비율로 조정합니다. 기본 10%는 10%포인트 가산이 아닙니다. 화면에 최종 표를 표시하고 구매 결과에도 적용 표를 저장합니다.

캠페인과 참여 보상

SAVE_CAMPAIGN은 금액·기간·종류·지급액·상품·횟수 등을 저장합니다. 기본 구간은 100만·200만·300만·500만·1,000만원이며 points/cash/box/burning/product를 지원합니다. 기간은 한국 날짜 기준, 반복 회차 목표는 기준금액×회차입니다. 동일 이벤트·회원·회차의 중복 지급을 막습니다.

회원가입은 최초 1회, 출석은 KST 하루 1회입니다. 추천은 본인·중복 등록을 제한하고 충전 조건을 확인합니다. 신원 기반 다중 가입 탐지는 구현하지 않았습니다. 실서비스는 인증 식별자와 심사 기준이 필요합니다.

캐시와 자동 전환

CASH_CONVERT는 상품 고정액 또는 기준가×기본60%를 캐시에 반영합니다. 금액과 기한은 당첨 시 보존합니다. PROCESS_DUE는 새 일반 상품의 240시간 만료와 3일·1일 전 알림을 처리합니다. 천장 상품·배송 요청·과거 기한 없는 상품은 제외합니다. 자동 전환은 보너스 포인트로 지급합니다. 페이지 실행·포커스·60초 점검으로만 동작하므로 서버 예약 작업을 별도 구축해야 합니다.

6. 실서비스 구현 순서와 운영 확정 사항

  1. 회원 인증과 관리자 권한부터 분리합니다. 일반 회원에게 관리자 API 접근을 허용하지 않고 역할별 조회·수정·환급 권한을 둡니다.
  2. 서버 DB에 회원별 지갑, 승인·취소 원장, 주문·당첨·재고를 구축합니다. 금액은 정수로 처리하고 거래번호·요청번호에 유일성 제약을 둡니다.
  3. PG 승인·취소 콜백을 검증합니다. 승인·원장·천장 적립을 하나의 거래로 처리하고 중복 콜백과 순서 역전·실패 재시도를 검증합니다.
  4. 서버 추첨과 재고 예약을 구현합니다. 잔액 차감·재고 차감·당첨·천장 수령·이벤트 지급이 원자적으로 성공하거나 실패하도록 구성합니다.
  5. 이미지 저장소, 업로드 검증, 배송 연동, 알림 발송과 예약 전환 작업을 연결합니다. 작업 재시작과 중복 실행에도 한 번만 처리되게 합니다.
  6. 관리자 승인 이력과 변경 전후 값을 서버에 보존합니다. 배포·접근권한·모니터링·백업 복구를 구성하고 운영 검수 후 공개합니다.

운영사와 확정할 내용

보상 수령 후 취소 시 상품 회수·캐시 회수·채무 조정의 순서, 사용한 이벤트 보상 회수, 품절 대체상품 동의, 자동 전환 전 통지와 이의 접수, 캐시 유효기간·소멸·현금성 여부를 확정해야 합니다. 현재 제작본은 정산 검토 기록을 남기며 실물 회수나 계좌 출금을 실행하지 않습니다.

가입 연령, 미성년자 절차, PG 취급 가능 여부, 확률형 판매의 법적 분류, 전자상거래 청약철회와 선불 잔액 규율, 개인정보 수집·위탁·제3자 제공을 사업 구조에 맞춰 별도로 검토해야 합니다. 현재 동의 선택은 기록하지만 실제 본인인증이나 필수 동의 강제는 시연을 위해 완화했습니다.

개발 견적과 일정은 인증·PG·상품 공급·배송 제공자, 서버 구조, 운영 정책을 확정한 뒤 산정합니다. 현재 문서에는 근거 없이 개발비나 납기를 확정하지 않았습니다.

7. 검수 기준과 현재 확인 결과

검수 항목통과 기준
결제와 재시도같은 요청번호로 재전송해도 승인·잔액·재고·보상은 한 번만 반영
천장4천만원에서 B 4회와 A 1회 가능, 초과금액 이월, 일반 당첨 초기화 없음
취소와 회원 분리부분 취소 합계가 원금을 넘지 않음, 타회원 환급은 그 회원 지갑에만 반영
재고와 실패 원자성품절·잘못된 확률·만료 상품 실패 시 잔액과 다른 기록에 부분 반영 없음
확률공개 표와 추첨 경계 일치, 합계100%, 과거 거래표 불변
전환전환액 스냅샷 유지, 만료 후 환급 차단, 자동 전환 중복 없음
이벤트KST 기간·다음회차 목표·최대횟수·중복 지급·버닝 표 일치
UI와 저장업로드 이미지 반영, 관리자 변경 사용자 반영, 모바일 넘침·폼·오류 표시 확인

수정 후 자동 테스트 120개가 통과했습니다. 이 중 독립 QA가 추가한 경계 테스트는 15개입니다. 별도 사용자·관리자 상태 연동 하네스 14개도 통과했습니다. 실제 Chrome에서 충전, 독립 A/B 수령, 부분 취소 후 정산 반영을 확인했으며 모바일 천장·상품 화면의 가로 넘침도 점검했습니다.
