# 랜덤박스 실서비스 전환 검증

충전한 포인트로 랜덤박스를 구매하고 당첨 상품을 받는 핵심 흐름은 구현되어 있습니다. 다만 현재 공개 페이지는 브라우저 저장 방식의 프로토타입입니다. 화면과 정책 안내를 보완한 상태이며 실제 영업이 가능한 결제·인증·배송·보안 시스템은 아닙니다. 아래 운영 전 필수 요건을 충족하기 전에는 실제 충전금이나 개인정보를 받아서는 안 됩니다.

## 누락 페이지와 반영 내용

| 구분 | 반영 내용 | 관리자 연결 | 남은 실제 연동 |
| --- | --- | --- | --- |
| 사업자 안내 | 상호·대표·등록번호·신고번호·주소·고객센터·반품주소·보호책임자 | 약관·정책에서 공개 정보 저장 | 실제 사업자 등록정보 확인 |
| 개인정보 처리방침 | 별도 페이지, 처리 목적·항목·권리·위탁 확정 항목 안내 | 정책 유형 privacy | 실제 보유기간·수탁자·국외 이전 현황 확정 |
| 포인트 정책 | 유상·보너스, 미사용 취소, 부분 사용 검토, 상품 전환 구분 | 충전·환급·전환 설정과 정책 본문 | PG 부분취소·환급 산식 승인 |
| 취소와 반품 | 법정 청약철회와 미수령 환급을 구분한 안내·접수 | 기존 1:1 문의로 거래번호·사유·답변 연결 | 반품 회수·검수·원결제 환불 |
| 배송과 보관 | 배송 지연·품절·하자 안내, 반품 주소 | 배송 설정·사업자 안내 | 실제 출고·택배 추적·회수 |
| 계정 복구 | 이메일 기반 복구 요청 화면 | 기존 1:1 문의 | 이메일 인증·일회용 재설정 토큰 |
| 회원 탈퇴 | 잔액·상품 확인 후 탈퇴 요청 | 기존 1:1 문의 | 본인확인·미결 거래 정리·개인정보 파기 |
| 개인정보 권리 | 열람·정정·삭제·처리정지·동의철회 요청 | 기존 1:1 문의 | 본인확인·법적 처리기한·실제 삭제 |
| 거래 명세 | 본인 충전·구매·배송 내역과 당시 정책 표시 | 거래 기록·원장 | PG 영수증·세금계산서 등 증빙 |
| 가입 동의 | 필수 안내와 선택 알림 분리, 기본 미선택, 선택값·정책 기록 | 회원 상세에서 선택 기록 확인 | 실제 필수 동의 검증·연령·법정대리인 확인 |
| 당첨 공개 | 회원 공개 선택과 이름 가림, 본인 기록은 유지 | 당첨 공개 설정·회원정보 | 전체 회원 서버 기록·동의 검증 |
| 정책 변경 | 유형·버전·시행일, 미래 시행 제외, 유형별 최신 적용 | 약관·정책 | 변경 사전 고지·재동의·배포 승인 |
| 잘못된 주소 | 없는 페이지 안내 및 홈·고객센터 이동 | 해당 없음 | 서버 오류 페이지·장애 안내 |

관리자 메뉴는 핵심 23개를 유지했습니다. 탈퇴·권리·반품 요청은 별도 관리자 메뉴 대신 고객 문의에서 처리합니다. 요청 접수는 잔액 지급, PG 환불, 회원 삭제를 실행하지 않습니다. 안내상 완료와 실제 환불 완료를 동일시해서는 안 됩니다.

사업자 정보는 사실 확인 없이 만들지 않았습니다. 미등록 항목은 등록 예정으로 표시됩니다. 정책 초안에 기재된 실제 운영 미확정 항목을 그대로 둔 채 영업을 개시하면 안 됩니다.

## 반드시 구분할 거래 정책

미사용 충전 취소는 충전 원금과 보너스를 회수하는 절차입니다. 상품 미수령 환급은 당첨 상품을 받지 않고 별도 조건으로 구매가 일부를 포인트로 되돌리는 기능입니다. 상품 전환은 상품 가치를 기준으로 보너스를 지급하는 별도 선택입니다. 법정 청약철회·반품에는 각각의 법정 요건과 비용 부담 기준을 적용해야 합니다. 네 가지를 하나의 환불 수수료로 처리하지 않아야 합니다.

전자상거래의 일반적인 청약철회 기간과 법정 예외, 표시·광고와 다른 공급, 비용 부담 및 환급 시점은 거래 유형별로 검토해야 합니다. 적법한 청약철회에 위약금 성격의 수수료를 일괄 적용하지 않도록 화면을 분리했습니다. 랜덤박스 개봉만으로 철회가 전부 배제되는 것으로 안내하지 않습니다. 구체적인 판매 방식에 대한 최종 법률 판단은 별도 필요합니다. [국가법령정보센터 전자상거래법](https://law.go.kr/LSW/LsiJoLinkP.do?docType=JO&joNo=004000000&languageType=KO&lsNm=%EC%A0%84%EC%9E%90%EC%83%81%EA%B1%B0%EB%9E%98+%EB%93%B1%EC%97%90%EC%84%9C%EC%9D%98+%EC%86%8C%EB%B9%84%EC%9E%90%EB%B3%B4%ED%98%B8%EC%97%90+%EA%B4%80%ED%95%9C+%EB%B2%95%EB%A5%A0&paras=1), [청약철회 수수료 관련 판례](https://law.go.kr/precInfoP.do?precSeq=205672).

개인정보 처리방침과 가입 동의는 역할이 다릅니다. 목적·항목·기간·법적 근거를 정리하고 선택적 알림 동의를 분리해야 합니다. 개인정보 처리 위탁 현황도 실제 계약에 맞게 공개해야 합니다. 현재 화면은 이를 확정한 운영 방침이 아니라 연동 범위와 남은 확정 항목을 안내합니다. [개인정보 보호법 처리방침 규정](https://www.law.go.kr/lsInfoP.do?chrClsCd=010202&lsId=011357&lsiSeq=182015&urlMode=lsEfInfoR&viewCls=lsPtnThdCmp), [현재 개인정보 처리 위탁 규정](https://law.go.kr/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900079876).

포인트는 이름만으로 규제 대상 여부가 결정되지 않습니다. 사용처, 가맹점 관계, 발행 규모와 환급 구조를 확인해야 합니다. 금융위원회의 2025년 안내는 등록 면제 요건과 충전금 보호를 설명하지만, 본 사업이 면제 대상이라는 판단 근거로 사용하지 않았습니다. 현금 환급·전환 반복, 확률형 상품의 판매 구조와 사행성·게임물 해당 가능성은 변호사 및 PG에 사업 모델을 제시해 별도 확인해야 합니다. [금융위원회 선불업 등록 안내](https://www.fsc.go.kr/po010101/84178?curPage=89&srchBeginDt=&srchCtgry=&srchEndDt=&srchKey=&srchText=).

운영 안정성은 기존에 제거한 관리자 운영현황·백업 메뉴를 다시 추가한다는 뜻이 아닙니다. 개발·인프라 운영 영역에서 구현할 필요가 있습니다.

홈 배너는 현재 등록 자료만 저장하며 메인 배너에 자동 연결되지 않습니다. 이벤트는 참여 기록만 남기고 자동 보상을 지급하지 않습니다. 알림 체크박스는 실제 문자·이메일 발송을 보장하지 않습니다. 포인트샵·트레이드는 부가기능 비활성 상태를 유지하며 해시패스를 새로 노출하지 않았습니다.

## 서버 데이터와 처리 기준

회원, 동의 이력, 관리자 역할, 정책 버전, 박스 버전, 상품, 재고 예약, 충전, 결제 승인, 포인트 원장, 박스 주문, 개봉 결과, 보관 상품, 전환, 배송 주문, 반품, 환급, 문의 및 감사 기록을 분리해야 합니다. 공개 당첨 데이터와 관리자 개인정보 조회도 별도로 제공해야 합니다.

구매는 회원 확인 → 사용 가능 잔액·정책·박스 버전 확인 → 재고 예약 → 서버 추첨 → 포인트 차감·주문·결과 저장을 하나의 트랜잭션으로 처리합니다. 개봉 애니메이션은 이미 확정된 결과만 재생합니다. 재시도 키를 받아 이중 차감과 이중 당첨을 막아야 합니다.

충전은 승인 전 잔액을 늘리지 않습니다. PG 승인과 웹훅을 검증하고 거래 원장에 한 번만 반영합니다. 취소·반품 접수와 실제 지급·환불은 분리하며, 완료 상태는 원장 및 PG 결과와 대사합니다. 배송비는 포인트 결제 또는 PG 결제 중 실제 수단을 정해 반영해야 합니다. 현재 배송 화면은 신청 기록만 저장합니다.

## 검증 기록

코드 검증은 저장·복원, 금액·재고·확률 검증, 충전 취소, 중복 환급 차단, 사용자·관리자 상태 전이, 정책 스냅샷, 요청 연결, 본인 데이터 필터를 실행합니다. 실제 PG·인증·택배·다중 회원 서버·동시성·법적 적합성은 현재 하네스의 통과 범위에 포함하지 않습니다.

화면 검증은 공개 사이트의 기존 가입·정책·관리자 화면을 촬영한 뒤 로컬 수정 화면을 확인했습니다. 정책 표시 → 취소·반품 접수 → 관리자 답변 저장 → 사용자 새로고침 재조회 흐름을 확인했습니다. 빈 회원가입 → 모의 충전 승인 → 포인트 구매 → 박스 오픈 연출 → 당첨 결과 → 보관함 새로고침 재조회도 확인했습니다.

자동 테스트 72개, 상태 통합 하네스 14개가 모두 통과했습니다. GitHub에서 내려받은 수정 소스에서도 빌드·테스트·하네스를 재실행하여 같은 결과를 확인했습니다. 신규 경로 11개는 실제 브라우저에서 렌더링을 확인했고 데스크톱 1280px에서 문서 전체의 가로 넘침이 없었습니다. Chrome 공개 배포 화면에서 390px 모바일 크기로 정책·취소반품·가입·마이페이지·박스 목록 5개 경로의 가로 넘침이 없고 신청 폼이 한 열로 표시되는 것을 확인했습니다. 이는 브라우저 반응형 확인이며 모바일·태블릿 실기기 및 전체 접근성 검수는 별도로 필요합니다.
