# 미팅 시연 및 검수 보고

사용자 거래 흐름과 관리자 47개 메뉴를 같은 데이터로 연결했습니다. 관리자 작업 124개의 상세 시연 방법은 `관리자-실행기능.md`에 정리했습니다. 이 수는 독립된 시스템이나 외부 연동의 수가 아닙니다.

## 시연 순서

1. 회원가입·로그인 폼을 비운 상태로 완료합니다.
2. 충전에서 금액과 결제수단을 선택하고 빈 결제폼으로 승인합니다. 지갑에서 유료/보너스 잔액을 확인합니다.
3. 미사용 충전 취소를 선택하여 원금·보너스 회수와 취소 이력을 확인합니다.
4. 박스의 공개확률과 수량을 확인하고 결제·개봉합니다. 결과와 보관함을 확인합니다.
5. 미수령 환급에서 기준가·수수료·순환급액을 확인하고 포인트 또는 원결제 모의 환불을 선택합니다.
6. 관리자에서 환급 자동승인을 해제한 후 사용자 신청 → 관리자 승인/반려 → 사용자 결과를 확인합니다.
7. 금액대별 확률을 바꾸고 평균 당첨횟수·N회 누적확률·50%/90% 도달횟수를 확인합니다.
8. 공지·이벤트·약관 등록과 사용자 노출, 문의 등록과 관리자 답변을 시연합니다.
9. 충전금액·보너스·배송비·무료배송 기준·회원 포인트를 바꾸고 사용자 반영을 확인합니다.
10. 당첨·신뢰센터에서 직접 개봉기록과 가상회원 샘플을 구분하고 개봉 당시 확률표를 확인합니다.

## 확률 계산

평균 대기횟수는 100/p입니다. N회 안에 한 번 이상 당첨될 확률은 1−(1−p/100)^N입니다. 50%·90% 도달횟수는 log(1−목표확률)/log(1−p/100)을 올림합니다. 0%는 당첨 불가, 100%는 1회입니다. 평균 횟수는 당첨 보장이 아니며 동일 확률로 독립 추첨하는 가정입니다.

## 직접 확인한 결과

- 빈 입력 가입 완료
- 30,000원 충전 및 900P 보너스 반영
- 충전 취소 후 30,900P 회수와 취소 완료 기록
- 9,900원 박스 개봉 후 상품 보관과 개봉 이력 생성
- 10,000원 상품에 10% 수수료를 공제하여 9,000P 환급
- 확률 합계 100.5% 저장 차단
- 1%/4.5%/15%/79.5% 저장 후 사용자 결제 확률표 반영
- 관리자 공지 등록 후 사용자 목록 노출
- 390px 모바일 당첨·신뢰센터 확인
- 상태 테스트: 충전·개봉·환급·반려·취소·무료배송·원결제환불·중복방지·설정 반영

개발서버 재시작 전에 열린 탭에서 Vite 연결 로그가 남았으나 새로고침 후 기능 시연은 정상 완료했습니다. 과거 `design-qa.md`는 최초 디자인 검수 기록이며 이번 변경 검수는 이 문서를 기준으로 합니다.

## 데이터 및 신뢰 표시

직접 시연한 개봉은 현재 브라우저의 기록입니다. 다른 회원 예시는 가상회원 샘플로 명시합니다. 개봉 당시 확률표를 별도로 저장하므로 이후 관리자 설정 변경으로 과거 기록이 바뀌지 않습니다. 현재 화면은 서버 추첨 원장이나 제3자 공정성 인증이 아닙니다.

관리자 거래와 사용자 잔액·재고·상태가 연결되는 핵심 흐름과, 운영자가 입력한 자료를 보관하는 보조 CRUD 메뉴를 구분했습니다. 실제 PG·송금·택배·데이터베이스는 연결하지 않았습니다. GitHub 공유용 상대경로와 수동 Pages 배포 설정까지 준비했으며 실제 업로드는 수행하지 않았습니다.
