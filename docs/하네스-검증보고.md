# 랜덤박스 하네스 검증 보고

핵심 거래 흐름의 자동 테스트와 브라우저 시연을 완료했습니다. 자동 테스트 38개, 상태 전이 통합 하네스 14개가 통과했으며 프로덕션 빌드도 성공했습니다. 관리자 50개 메뉴와 사용자 추가 서비스 15개는 실제 버튼으로 이동하여 화면 표시를 확인했습니다.

## 검증 결과

| 구분 | 결과 | 확인 범위 |
| --- | --- | --- |
| 자동 테스트 | 38개 통과 | 거래 엔진 34개 및 정적 배포 패키징 4개 |

메뉴 접근 검증은 모든 등록과 수정 조합을 검증했다는 의미가 아닙니다. 거래 상태는 자동 테스트로, 실제 화면 연결은 아래 시나리오로 나눠 확인했습니다.

## 실제 화면에서 확인한 거래

빈 입력으로 회원가입과 로그인을 완료했습니다. 30,000원을 모의 충전하면 보너스 900P가 반영되며, 취소하면 두 금액이 함께 회수됩니다.

장바구니에 9,900원 박스를 담고 결제 화면으로 이동했습니다. 웰컴 쿠폰 10%를 적용하여 990원 할인, 최종 결제 8,910원을 확인했습니다. 결제정보를 입력하지 않고 개봉을 완료했으며 결과가 보관함에 반영되었습니다.

당첨 상품을 7,000P로 전환한 다음 복구하여 상품이 다시 보관 상태로 돌아오는 것을 확인했습니다. 이어서 미수령 환급을 신청했을 때 구매가 8,910원에서 수수료 891원을 차감한 8,019P가 반영되었습니다. 관리자 대시보드에서도 사용자 잔액 120,019P를 확인했습니다.

관리자 확률표에서는 1%에 대해 평균 100회당 1회, 100회 중 1회 이상 당첨 확률 63.3968%, 50% 도달 69회, 90% 도달 230회가 표시되었습니다. 평균 횟수는 당첨 보장과 구분하여 안내합니다.

## 수정 및 보강 사항

- 재고가 없는 당첨 구간에서 임의 상품권을 생성하던 처리를 제거했습니다. 유효한 확률구간의 재고가 부족하면 거래 전체가 거절됩니다.
- 상품별 최종 당첨 확률과 평균 횟수를 표시했습니다.
- 구매가, 할인액, 원결제 수단, 유료 포인트와 보너스 사용분을 보관 상품에 기록하도록 보강했습니다.
- 환급 화면과 관리자 예상 환급액을 구매가 기준으로 맞췄습니다. 상품 포인트 전환은 상품 가치와 전환율을 사용하는 별도 기능입니다.
- 포인트 구매 환급은 유료와 보너스를 나눠 반환합니다. 보너스가 유료 잔액으로 바뀌는 것을 방지했습니다.
- 전환 복구 시간과 횟수, 쿠폰 재사용, 재고 부족, 중복 환급, 배송 이후 환급을 검증했습니다.
- 관리자 운영 진단, 백업과 복원, 메뉴 검색, 배송 상태 연결, 실패 시 오류 유지 기능을 보강했습니다.
- 모바일에서 접힌 관리자 메뉴를 숨겨 키보드 탐색에 남지 않도록 수정했습니다.

## 시연 범위와 남은 운영 설계

실제 결제, 본인 인증, 송금, 택배사, 외부 알림과 데이터베이스는 연결하지 않았습니다. 공급사, 정산, 권한 등 보조 메뉴는 기록 관리 시연이며 실제 정산이나 접근 권한 강제를 수행하지 않습니다. 선물과 트레이드의 소유권 이전, 보관 만료 자동 처리, 확률 버전별 실측 집계와 전체 원장 대사는 별도 고도화 항목입니다. 해당 기능까지 실서비스 수준으로 검증된 것은 아닙니다.

현재 확률과 상품 구성은 시연용입니다. 매입원가 미입력 상품은 상품 가치로 추정하므로 원가율을 사업 수익성으로 판단하면 안 됩니다. 관리자 예상 환급액은 쿠폰을 사용하지 않은 1회 구매 기준이며 실제 환급은 할인 반영된 구매가로 계산됩니다.

브라우저 로그 조회에서 오류 항목은 반환되지 않았습니다. 이는 이번 조회 범위의 결과이며 모든 기기와 브라우저의 무오류를 보장하지 않습니다. 브라우저에는 이번 검증으로 생성한 모의 거래 기록이 남아 있습니다.
